LumineEconomyBridge 機能ガイド

LumineEconomyBridge は Minecraft のスコアボード経済を Python バックエンドと Web ダッシュボードに橋渡しするプラグインです。本ページではインストールから高度な応用例まで懇切丁寧に解説します。

1. 仕組みと構成

LumineEconomyBridge は次の 3 コンポーネントで構成されます。

  • Spigot プラグイン: ゲーム内コマンドを受け取り、スコアボードを更新します。各コマンド実行時に保留中の差分をバックエンドへフラッシュし、表示とデータベースの整合性を保ちます。
  • Python バックエンド: FastAPI で経済ロジックを処理し、データベースへ保存します。
  • Web ダッシュボード: ブラウザから残高やショップを管理する管理画面を提供します。

プレイヤーがコマンドを実行するとプラグインが HTTP 経由でバックエンドへ送信し、処理結果がスコアボードとチャットに反映されます。ダッシュボードや外部ツールも同じ API を利用できるため、柔軟な拡張が可能です。

2. 環境とインストール

  1. Java 17 以上と Python 3.10 以上を用意し、pip install -r backend/requirements.txt で必要ライブラリを導入します。
  2. リリースから LumineEconomyBridge.jar をダウンロードしサーバーの plugins/ に配置します。
  3. サーバーを起動し、backend/ ディレクトリで python main.py を実行して FastAPI バックエンドを起動します。

3. 初期設定

  1. 生成された plugins/LumineEconomyBridge/config.yml の api.token と環境変数 LE_TOKEN を同じ値に設定します。
  2. 必要に応じて LE_API_BASE (バックエンドの URL) や MAPCOLOR_URL を環境変数で指定し、バックエンドを再起動します。
  3. スコアボードに「cash」オブジェクティブが存在しない場合は自動で作成されます。

4. プレイヤー向けコマンド

プレイヤーは以下のコマンドで自分の口座や取引を操作できます。

  • /le wallet : 自分の残高を一覧表示。初回実行時は口座が自動作成されます。
  • /le balance [currency] [player] : 任意プレイヤーの残高を確認。
  • /le pay <player> <amount> [currency] : 自分の資金から送金。
  • /le transfer <src> <dst> <currency> <amount> : 指定アカウント間で資金を移動。
  • /le deposit / /le withdraw : システムアカウント同士での入出金を記録。
  • /le money top [currency] [page] : 残高上位一覧を表示 (10 人/ページ)。
  • /le history <player> [limit] : 最近の取引履歴を確認。
  • /le shop : ショップ樽を受け取り設置すると自動でショップが作成されます。シフトクリックで売却も可能。
  • /le search <item> [currency] [min] [max] : 公開ショップを検索して価格比較。
  • /le lang <code> : 表示言語を切り替え (例: /le lang ja)。
  • /le weblink : ダッシュボードとの連携用トークンを発行。

5. ショップ機能

ショップ樽を使ってアイテムを売買できます。基本的な流れは以下の通りです。

  • /le shop create <id> : 任意の ID でショップ樽を作成。
  • /le shop add <id> <qty> <price> <name> : 在庫を追加し価格を設定。
  • /le shop price <id> <name> <currency> <amount> [more...] : 価格を複数通貨で変更。
  • /le shop take <id> <item> <qty> / remove : 在庫回収や商品削除。
  • /le shop partner add <id> <player> : 共同オーナーを追加し共同運営。
  • /le shop partner remove <id> <player> : 共同オーナーを削除。
  • /le shop account <id> <deposit|withdraw> <player> : ショップの入金・出金先アカウントを設定。
  • /le shop reopen <id> : 一時停止したショップを再開。
  • /le search <item> [currency] [min] [max] : 公開ショップを検索し最安値を探す。
  • プレイヤーは在庫のあるショップにアイテムをシフトクリックすると売却確認メニューが表示されます。

紙幣アイテムは ID が異なっていても同じ額と通貨であれば同一の商品として扱われます。

発行済みの紙幣はチェスト内やプレイヤーのインベントリに入ったシュルカーボックス内でもバックエンドに記録され、常に所在を追跡できます。

6. Web ダッシュボード

  1. ゲーム内で /le weblink を実行してワンタイムトークンを取得します。
  2. ブラウザで /register にアクセスし、ユーザー名・パスワード・トークンを入力して登録します。
  3. /login からログインすると、残高確認やショップ管理、ショップ検索などが利用できます。

ダッシュボードでは以下の管理ツールを提供します。

  • アカウント検索・編集、通貨供給量のグラフ表示。
  • 取引履歴のフィルタリングと CSV エクスポート。
  • ショップ一覧と価格変更、掲載/非掲載の切り替え。
  • コマンドログビューアやメトリクスグラフ。
  • バックアップの作成・復元・スケジュール管理。

7. 管理者向け機能

  • /le money give <player> <currency> <amount> / take : プレイヤーの資金を発行・没収。
  • /le currency create <id> [symbol] : 新しい通貨を作成。
  • /le currency supply [id] : 通貨の総供給量を表示。
  • /le currency default <id> : デフォルト通貨を変更。
  • /le currency manager add/remove <id> <player> : 通貨管理者の追加・削除。
  • /le currency tax <id> <rate%> と treasury : 税率と納付先アカウントを設定。
  • /le account create <id> や connect <user> <system> : システムアカウントの作成・紐付け。
  • /le setbalance <player> <currency> <amount> : 任意の残高へ直接設定。
  • /le admin add <player> : ダッシュボード管理者に追加。
  • /le backup / /le restore <file> : データベースのバックアップ・復元。
  • /le undo / /le redo : 最近の操作を取り消し/やり直し。

8. REST API 連携

バックエンドは FastAPI を用いた REST API を提供しており、外部ツールからサーバーの経済データを取得・操作できます。

  1. 環境変数 LE_TOKEN を利用し、HTTP ヘッダー Authorization: Bearer <token> を付与してリクエストします。
  2. GET /wallet/<player> : 任意プレイヤーの残高を取得。
  3. GET /currency : 登録通貨の一覧と供給量を取得。
  4. POST /transfer : JSON で送金内容を送り、サーバー外から自動送金。
  5. GET /shops/search : アイテム名で公開ショップを検索。
  6. GET /api/cash/note/<note_id> : 指定した紙幣の最新位置と履歴を取得。

例: Python から残高を取得する簡単なスクリプト

import requests
resp = requests.get(
    "http://localhost:8000/wallet/Steve",
    headers={"Authorization": "Bearer YOUR_TOKEN"},
)
print(resp.json())

9. 応用例

以下では代表的な応用シナリオを章立てで紹介します。

9.1 複数通貨と経済圏の分離

/le currency create で新通貨を作成し、manager add で管理者を委任すると、ワールドや派閥ごとに独立した経済圏を運営できます。デフォルト通貨と交換レートを決めることで相互の貿易も可能です。

9.2 税収システムの導入

tax と treasury を設定すると、取引時に自動で税が徴収され国庫アカウントへ送金されます。徴税率を 0 に戻すまで有効で、/le history で税収の推移を確認できます。

9.3 ショップ網の構築と共同運営

複数のショップ樽を設置し partner add で仲間を追加すると、在庫や利益を共有する大規模なマーケットを形成できます。price コマンドで複数通貨の価格を同時に変更し、search で市場調査も行えます。

9.4 ダッシュボードによる監査とバックアップ

Web ダッシュボードでは取引履歴のフィルタリングや CSV エクスポート、定期バックアップのスケジュール設定が可能です。大規模な経済運営では不正検知や履歴管理に活用してください。

9.5 Python スクリプトで自動給与支払い

import requests

def pay_salary(player, amount, token):
    payload = {"src": "treasury", "dst": player,
               "currency": "credit", "amount": amount}
    requests.post(
        "http://localhost:8000/transfer",
        json=payload,
        headers={"Authorization": f"Bearer {token}"},
    )

# 例: プレイヤーのログインフックから呼び出す
pay_salary("Steve", 100, "YOUR_TOKEN")

9.6 外部データベース連携による可視化

API から取得した JSON を外部の BI ツールやデータベースに保存すると、取引量や通貨供給量の時系列グラフを作成できます。サーバーの経済状況を分析してバランス調整に役立てましょう。

9.7 サーバー間通貨共有

複数の Spigot サーバーが同じバックエンドデータベースに接続すると、プレイヤーは別ワールドでも共通の残高を利用できます。サーバーごとに LE_API_BASE を分ければ負荷分散も可能です。

10. トラブルシューティング

  • バックエンドに接続できない: トークン設定と LE_API_BASE を確認し、サーバーのポートが開いているか確かめてください。
  • ダッシュボードにログインできない: ユーザー登録時のトークンが正しいか、ブラウザの Cookie を削除して再試行してください。
  • ショップが動作しない: 樽が保護されていないか、価格と在庫が正しく設定されているかを確認してください。
  • スコアボードが更新されない: プラグインとバックエンドが起動しているか、LE_API_BASE の URL が正しいか確認します。
  • API が 401 を返す: Authorization ヘッダーとトークンの有効期限を確認し、必要なら新しいトークンを発行してください。

より詳細コマンド一覧は USAGE.md、ショップ運営の詳細は SHOP_HELP.md を参照してください。
